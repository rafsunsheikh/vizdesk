# Recording the demo

VHS would normally do this, but VHS needs `ttyd` and ttyd publishes no macOS
build, so `record.py` does the same job directly: it runs the app in a
pseudo-terminal of a fixed size, reads what the app draws with `pyte`, renders
each frame with Pillow, and hands the frames to ffmpeg.

Because it is scripted, the recording is identical every time. Nobody has to
drive a terminal by hand and nobody has to be careful about their window size.

## Rebuild it

```
python3 -m venv .venv-rec && .venv-rec/bin/pip install pyte pillow
.venv-rec/bin/python docs/recording/record.py
```

Then encode. The terminal flow runs to frame 276, and the closing seconds show
the figure vizdesk actually drew rather than the terminal's own preview, which
is necessarily blurry: a preview is squeezed onto the character grid, so text
turns to grey smear while the bars survive.

```
ffmpeg -y -framerate 12 -i /tmp/vdfinal/%05d.png \
  -vf "scale=1136:-2:flags=lanczos,pad=ceil(iw/2)*2:ceil(ih/2)*2" \
  -c:v libx264 -pix_fmt yuv420p -crf 20 -movflags +faststart docs/images/vizdesk-demo.mp4
```

## What to edit

`session.py` holds the keystrokes and the pauses. Edit that, not `record.py`.
Timings are deliberate: a demo that moves too fast reads as a blur, and the
first three seconds decide whether anyone keeps watching, which is why the file
is already loaded when the recording starts.

`workspace/` holds the sample data, generated by a script so the recording never
depends on a network or on somebody else's licence.

## Output

| file | use |
|---|---|
| `docs/images/vizdesk-demo.mp4` | Reddit, which plays video natively |
